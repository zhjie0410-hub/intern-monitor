## 一、统一字段口径（我们的标准）

| 字段 | 定义 | 缺失时 |
|---|---|---|
| `job_id` | 平台内岗位唯一 ID | 必填，无则不入库 |
| `batch` | 批次/招聘项目名（**28届 判断核心**） | 空 |
| `work_type` | 正式 / 实习 | 空 |
| `publish_time` | **官方**发布时间 | 空 |
| `published_days` | 距今天数 | -1 |
| `first_seen` | 我们第一次抓到 | 必有 |
| `fresh_days` | 统一新鲜度（官方优先，否则 first_seen） | -1 |
| `fresh_source` | `official` / `first_seen` | 必有 |

**去重键**：`公司::岗位ID`（不用标题，多城市会重复）。

## 四、口径差异的六个坑（重点）

### 坑 1：岗位总数不可横向比
```
字节 1817  ← 关键词命中 + work_type=实习（校招正式岗混在里面）
腾讯   73  ← 只数 projectMappingIdList=104 一个池
滴滴  298  ← 整个 Moka 站就是实习专区
快手/网易/拼多多 ← 待测
```
要比较只比「方向过滤后」的数。

### 坑 2：发布时间三种口径
| 情况 | 公司 | 处理 |
|---|---|---|
| 官方提供 | 字节、快手、拼多多、网易、得物 | 直接用 |
| 完全不提供 | 腾讯（已确证） | 用 `first_seen` + `fresh_source=first_seen` |
| 响应加密看不到 | 滴滴（Moka） | 待测 DOM 是否显示日期 |
| 未确认 | 其余 | 实现时验证并补进本表 |

### 坑 3：28届判定依据每家不同
| 依据 | 公司 |
|---|---|
| `work_type == 实习` | 字节、得物 |
| 招聘项目 id（`projectMappingIdList=[104]`） | 腾讯 |
| 招聘项目名（日常实习项目） | 得物 |
| URL 参数 `workType=1` | 网易 |
| 独立入口路由（`/trainee/`） | 快手 |
| 独立接口（`position/train/list`） | 拼多多 |

**统一做法**：每家写一个 `is_intern(job)`，注释写清依据。

### 坑 4：城市格式不统一
| 公司 | 格式 | 处理 |
|---|---|---|
| 字节 | 数组 `[{name}]` | 取 name，`/` 连接 |
| 腾讯 | 空格串，含「深圳总部」 | 替换成「深圳」 |
| 其他 | 待确认 | 实现时记录 |

### 坑 5：接口返回可能是密文
滴滴的 Moka 接口 `data` 字段是密文（AES/RSA），**不能解析** → 必须读 DOM。
判断方法：看响应里 `data` 是不是 base64 长串。

### 坑 6：同一家站点可能用第三方 SaaS
- 滴滴 = **Moka**（`app.mokahr.com`）
- shopee = **workatsea**（`ats.workatsea.com`）
- 得物 = **字节同款**（`campus.dewu.com` + `starling.zijieapi.com`）

识别出 SaaS 后，**同 SaaS 的公司可以复用一套代码**，这是省时间的关键。

## 六、补充（2026-11-22 晚，三处修正）

### 修正 1：滴滴 **有**发布时间（之前判断错）

接口（Moka）返回的是密文，但**页面 DOM 里直接显示**：

```
数据分析实习生（国际化）-MJ020806   发布于 2026-11-16   实习 | 数据 | 本科 | 上海市
战略业务事业群-数据科学实习生（MJ020759）发布于 2026-11-10
国际事业群IBG-数据分析实习生（MJ020755） 发布于 2026-11-10
用户平台部-数据分析实习生（MJ020745）   发布于 2026-11-09
```

- 格式：`发布于 YYYY-MM-DD`
- 提取方式：读 DOM 文本，正则 `发布于\s*(\d{4}-\d{2}-\d{2})`
- 数据分类（`zhineng[0]=134766`）共 12 个岗位，日期跨度 2026-08-06 ~ 2026-11-16
- **口径结论**：滴滴 `publish_time` = 官方提供（从 DOM 取），`fresh_source = official`

### 修正 2：百度 **不需要浏览器**，且有 491 个实习岗

百度用的是**服务端渲染**，数据内嵌在 HTML 里：

```javascript
window.__USE_SSR__ = true;
window.__INITIAL_DATA__ = { layoutData, detailData, listData, indexData }
```

`listData.listDetailData` 里每个岗位包含：

| 字段 | 示例 |
|---|---|
| `name` | 数据分析实习生（J107382） |
| `postId` / `jobId` | uuid |
| `postType` | 技术 / 数据 … |
| **`publishDate`** | **2026-07-08** ✅ |
| `updateDate` | 2026-08-05 |
| `workContent` / `serviceCondition` | JD 与要求 |
| `workPlace` / `education` / `projectType` | 城市/学历/项目 |

**关键参数**：`https://talent.baidu.com/jobs/list?recruitType=INTERN` → `total=491`（实习岗 491 个）

注意事项：
1. JSON 里有 JS 的 `undefined`，必须先 `re.sub(r'\bundefined\b', 'null', raw)` 才能 `json.loads`
2. **分页参数未通**：`pageNum` / `page` / `pageIndex` / `currentPage` / `offset` 全都无效，每页固定 10 条（SSR 只给第一页）

## 七、百度攻关记录（2026-11-22 晚，结论：暂时抓不全）

### 能做到的
- `https://talent.baidu.com/jobs/list?recruitType=INTERN` 是**服务端渲染**
- `window.__INITIAL_DATA__.listData.listDetailData` 里有 10 条完整岗位（含 `publishDate`）
- `total=491` —— 百度实习岗共 491 个

### 卡住的地方
| 试法 | 结果 |
|---|---|
| 分页参数 `pageNum` / `page` / `pageIndex` / `currentPage` / `offset` / `pageNo` / `p` / `pageNumber` / `curPage` / `no` / `start` / `begin` / `pageSize` | 全部无效，始终返回第 1 页 10 条；部分参数会让 total 变 0 |
| 关键词参数 `keyword` / `keyWord` / `k` / `query` / `searchKey` / `postName` | 无效（`keyword=` 直接 0 结果） |
| 筛选参数 `postType` / `workPlace` / `projectType` | 无效 |
| 猜 JSON 接口 `/api/jobs/list` 等 9 个路径 | 404 |
| JS bundle 找接口 | 只命中 `pageNum` 字样，没有明文 API 路径（在 webpack 懒加载 chunk 里） |
| Playwright 打开（含 stealth + 忽略证书 + `--disable-blink-features`） | 始终变成 `about:blank`，正文 0 字 |
| urllib 直取 | ✅ 正常（102KB）——说明是 chromium 侧 abort，不是服务端拒绝 |

### 结论
**百度目前只能拿到 491 个里的前 10 个，分页与筛选都拿不到。** 不是参数没猜对就是客户端接口藏在懒加载 chunk 里。

### 三个备选方案
| 方案 | 成本 | 效果 |
|---|---|---|
| A. 先用实习僧覆盖百度 | 0（已有 4 个百度岗） | 覆盖部分，不完整 |
| B. 逆向 webpack chunk 找接口 | 半天-1 天 | 能抓全 491，但要读混淆代码 |
| C. 放弃百度 | 0 | 无 |

建议先 **A**，等其余公司都接完、有余力再回头做 B。

## 十、收尾攻关：美团时间 / 蚂蚁接口 / 滴滴 DOM / 百度

### 1. 美团 ✅ 时间字段确认

```
POST /api/official/job/getJobList
body: {"page":{"pageNo":1,"pageSize":10},"jobShareType":"1","keywords":"",
       "cityList":[],"department":[],"jfJgList":[],
       "jobType":[{"code":"1","subCode":[]},{"code":"2","subCode":[]}],
       "typeCode":[],"specialCode":[],"u_query_id":"..."}

响应 data.list[] 字段：
  jobUnionId, name, projectId, projectName, jobType, jobStatus,
  jobFamily, cityList, workYear,
  firstPostTime   ← 可能为 null
  refreshTime     ← 有值（1786960999000，毫秒时间戳）✅
  expiredTime     ← 可能为 null
```

**口径**：`publish_time` 取 `refreshTime`；`firstPostTime` 为空时也无所谓（它才是"首次发布"，多为 null）。

### 2. 蚂蚁 ✅ 打通

```
POST https://hrcareersweb.antgroup.com/api/campus/position/search?ctoken=bigfish_ctoken_xxx
body: {"channel":"campus_group_official_site","language":"zh","regions":"","subCategories":"",
       "bgCode":"","pageIndex":1,"pageSize":10,"recruitType":[],
       "batchIds":["25051200066269"]}

响应 data.content[]：
  id, name, workLocations, tags,
  publishTime = "2026-11-13T11:25:21.000+00:00"   ← ISO 格式 ✅
  graduationTime = {from, to}
```

**口径**：`publishTime` 是 ISO 8601 字符串（带时区），要转成 `YYYY-MM-DD`；
`batchIds` 决定批次（`25051200066269` = 实习生批次）。
需要 `ctoken` 参数（页面里带的 bigfish 风控 token），所以**必须走浏览器拿 URL**。

### 3. 滴滴 ⚠️ DOM 可读，但必须显式等待

### 4. 百度 ❌ 没有别的路（已穷举）

| 试法 | 结果 |
|---|---|
| `POST /jobs/list`（JSON body） | 返回 HTML 页面，不是接口 |
| 找 `apiBase` / `baseURL` / 其他 baidu 域名 | 只找到 home/hm/wappass，无接口域名 |
| 分页参数 13 个变体 | 全部无效 |
