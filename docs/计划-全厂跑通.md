# 计划：全部公司跑一遍

> 目标：把已确认接口的 10 家 + 滴滴（DOM）跑通，汇总进看板
> 原则：不写 10 份适配器，写 **1 个引擎 + 10 份规格**

---

## 一、为什么用「引擎 + 规格」

各家的差异只在四处，其余全一样：

| 差异点 | 例子 |
|---|---|
| 入口 URL | `campus.dewu.com/578078/position/list` |
| 列表接口 | `POST /api/v1/search/job/posts` |
| 分页字段 | 字节 `offset`、京东 `pageIndex`(0起)、美团 `page.pageNo`(1起) |
| 字段名 | 标题 `positionTitle` / `name` / `jobName`；时间 `publishTime` / `refreshTime` |

所以引擎负责：打开页面 → 触发请求 → **抓住真实请求（URL+头+cookies）** → 改分页参数重放 → 解析字段。
规格只描述上面四处差异。

**关键设计：重放而不是重造请求**
页面加载时会自己发一次请求（带 csrf/ctoken/u_query_id 等 token），我们把它抓下来，
只替换分页参数再发——token 天然是新鲜的，不用逆向。

## 二、执行步骤

| 步骤 | 内容 | 验收 |
|---|---|---|
| 1 | 写引擎 `src/scanners/generic.py`：抓包 + 重放 + 字段映射 | 能对任意 spec 返回岗位数组 |
| 2 | 写规格 `src/scanners/specs.py`：10 家 + 滴滴 | 每家一条 spec |
| 3 | 逐家跑，打印「抓到 N 条 / 前 3 个标题」 | 每家 > 0 |
| 4 | 失败的降级：改用「浏览器点下一页」模式 | 仍为 0 才判定失败 |
| 5 | 合并所有公司 → CSV → 重建看板 | 看板公司筛选里能看到多家 |

---

## 三、优先级（先易后难，跑出数据再补难的）

| 批次 | 公司 | 预估难度 | 理由 |
|---|---|---|---|
| **1** | 得物 | ★ | 与字节同接口 |
| **1** | 京东、拼多多、网易 | ★★ | 分页字段简单 |
| **2** | 快手、小红书、小米 | ★★ | 参数略多 |
| **2** | 阿里、蚂蚁 | ★★★ | 需要 csrf / ctoken |
| **3** | 美团 | ★★★ | 要先点筛选 |
| **3** | 滴滴 | ★★★★ | 只能读 DOM + 15 分类 |

---

## 四、验收标准

每家必须满足三条，否则记为失败：

1. 抓到 **> 0** 条岗位
2. 有一条能对上 **发布时间**（或明确标记为无）
3. 能区分 **实习 vs 非实习**（或 spec 里写清了固定过滤条件）
