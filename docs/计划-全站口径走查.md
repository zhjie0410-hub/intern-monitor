# 计划：全站口径走查

> 目的：把每家的「实习入口 → 岗位列表 → 字段口径」走一遍，产出一张可对照的口径表。
> 原则：**不急着写适配器，先把口径摸清**。口径不清就写代码，等于返工。

---

## 一、做法

写一个通用探针 `tools/probe_company.py`，对每家公司做固定的五步：

| 步骤 | 动作 | 记录什么 |
|---|---|---|
| 1 | 打开入口页 | 最终 URL、正文长度、是否 404/超时 |
| 2 | 扫描导航文字 | 是否有一级「日常实习 / 实习生 / 实习」入口 |
| 3 | 命中就点进去 | 点击后的 URL 变化 |
| 4 | 拦截所有 XHR | 岗位列表接口：method + path + 请求体 |
| 5 | 检查返回 JSON | 是否含时间字段（time/date/publish）→ 决定发布时间口径 |

## 三、产出物

1. `data/probe/<公司>.json` —— 每家的原始探测结果（可复查）
2. `docs/抓取口径记录.md` —— 人工汇总的对照表（唯一维护依据）
3. 一张「谁能做 / 谁要绕 / 谁放弃」的结论表

## 四、判定标准

| 判定 | 条件 |
|---|---|
| **可直接做** | 找到岗位列表接口 + 能区分实习 + 有发布时间 |
| **可做但需处理** | 找到接口，但缺发布时间 / 需点击两层 / 接口加密 |
| **暂缓** | 连不上 / 无实习入口 / 需登录才可见 |

## 五、不做什么

- 不在这轮写适配器（只摸口径）
- 不处理登录态
- 不碰 Moka 加密解密（滴滴改用读 DOM）
